## 1. Verdict

### 🔴 NO-GO en l'état — GO-CONDITIONNEL sous 7 conditions bloquantes

Le produit ne peut pas être lancé aujourd'hui : une clé API réelle est publiquement exposée, l'infrastructure serveur qui fait fonctionner le cœur du produit (chat, collecte audio, identité) n'est pas déployée, et la promesse d'anonymat affichée dans la politique de confidentialité est contredite par le code. Aucun de ces points n'est cosmétique. En revanche, tous sont corrigeables en quelques jours de travail ciblé : le verdict est donc **GO-CONDITIONNEL**, le lancement étant autorisé une fois les 7 conditions ci-dessous remplies.

**Conditions bloquantes (à lever avant tout lancement) :**

1. **Révoquer et purger tous les secrets exposés.** Rotation immédiate de la clé API Anthropic publique (SECRET Anthropic `sk-ant-…`), rotation du PAT GitHub valide à scopes quasi-totaux (SECRET PAT `ghp_…`), purge de l'historique git public et local. → couvre les secrets **Anthropic-P0**, **PAT-GitHub-P1**, et par ricochet le risque de fuite du reste (Apple .p8, Cloudflare, Firebase).

2. **Déployer et câbler les 3 workers Cloudflare, dans le bon ordre, puis désactiver le mode non signé.** → couvre **INFRA-01**, **INFRA-02**, **INFRA-03**, **SEC-03** (à compléter par le rate-limiting), et débloque **EXO-03** (collecte audio).

3. **Corriger la contradiction RGPD « anonyme » / « non transmis ».** Implémenter la suppression fail-closed du compte auth après émission du token, purger `verified_contacts` et le journal d'audit, et rendre la politique de confidentialité conforme à ce que fait réellement le code. → couvre **BACK-01**, **RGPD-01**, et par cohérence **SEC-02**.

4. **Supprimer le code du système de tokens abandonné (AES-GCM + flux PII).** Retirer les edge functions `decode-token` / `register-and-issue-token` / `verify-uniqueness` et le flux d'inscription email/téléphone du binaire. → couvre **SEC-01**, **SEC-02**, **SEC-08**.

5. **Réconcilier le code source et reconstruire le bundle web servi en production.** Faire un `git pull` du dépôt local (17 commits de retard), merger le seul worktree porteur de travail non porté (refonte scoring), puis reconstruire `main.dart.js` (16 commits Dart de retard). → couvre **INFRA-05**, **INFRA-07**, et active en prod les correctifs déjà écrits (**EXO-05**, **EXO-06**).

6. **Corriger le blocage total de la batterie sur retour arrière.** Un simple geste « retour » pendant un sous-test fige toute la session sans issue. → couvre **EXO-01**.

7. **Corriger le scoring verbal trivialement gonflable.** Le matching par sous-chaîne permet à une réponse de 3 lettres au hasard de marquer le maximum, invalidant le QI verbal. → couvre **SCOR-01**.

## 3. Ce qui est bon

**Sécurité des secrets (hygiène locale).** En dehors des deux fuites majeures (clé Anthropic publique et PAT GitHub), l'hygiène est largement correcte : le dépôt `mentality-shared` qui contient les secrets sensibles (clé privée Apple, service account Firebase, tokens Cloudflare) n'a **aucun remote** et son historique git est vierge de tout secret. Le service account Firebase est explicitement gitignoré. La vérification a confirmé qu'**aucune clé `service_role` Supabase ne fuite côté client** — seule la clé anonyme publique (conçue pour cela) est présente. Les faux positifs classiques (placeholders `votre-clé-ici`, `max_tokens`) ont été écartés.

**Architecture d'identité anonyme (la cible).** Le nouveau système de tokens Ed25519 est bien conçu sur le fond : `createdAt` est volontairement arrondi à minuit UTC (anti-corrélation), le token est immuable, et la vérification de signature est réellement appliquée côté serveur (r2-upload et claude-proxy rejettent en 401 tout token non signé). Le problème n'est pas le design cible mais le fait qu'il coexiste avec l'ancien système PII et qu'il tourne encore en mode « non signé » de beta.

**Résidence des données EU.** Le worker r2-upload applique correctement une juridiction EU (`--jurisdiction eu`) pour le stockage audio, avec une documentation RGPD explicite. C'est le bon réflexe ; il reste à l'étendre au chat (voir INFRA-09).

**Honnêteté psychométrique partielle.** Le disclaimer « indicatif, non diagnostique » est réellement affiché à l'utilisateur, ce qui atténue le risque juridique des normes synthétiques. La règle de discontinuation WAIS-IV (3 échecs consécutifs) est correctement implémentée. Les bugs Balances (fractions, jetons négatifs) et Matrices (options blanches invisibles) sont **déjà corrigés dans le code source** — ils ne persistent qu'en production faute de rebuild.

**Travail en cours de qualité.** Le worktree `practical-montalcini` (refonte scoring paramétrique âge-relatif) et le WIP admin (feature « Notes d'amélioration », refonte PreviewPage, durcissement du grain d'horodatage token) sont du travail cohérent et fonctionnel, pas du détritus. La reprise de session partielle (au niveau du sous-test) existe déjà.
